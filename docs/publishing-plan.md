# Publishing Plan

## Purpose

Build a publishable body of work around getting more out of Codex in agentic work: how to frame tasks, manage context, verify outcomes, use sub-agents, preserve project memory, and keep AI-assisted work operationally grounded.

## Audience

- Builders already using Codex who want a stronger operating model.
- Technical leads shaping AI-assisted engineering workflows.
- Operators turning recurring AI work into reusable playbooks, checklists, and repo patterns.

## Positioning

Codexmaxxing should feel practical, opinionated, and field-tested. It should avoid vague AI productivity language and avoid pretending that agentic work is magic. The useful claim is narrower: Codex becomes more valuable when the work surface is engineered.

## Initial Content Set

1. The Codexmaxxing thesis: what changes when Codex is treated as a working surface.
2. Task framing: turning vague asks into verifiable operating contracts.
3. Context control: what to read, what to ignore, and how to avoid stale assumptions.
4. Verification loops: making completion claims defensible.
5. Delegation patterns: when sub-agents help and when they add drag.
6. Publish-safe examples: how to sanitize local workflows into reusable guidance.
7. Team adoption: moving from individual tool usage to measurable workflow capability.

## Release Shape

The first public release should include:

- A direct README with a clear thesis.
- Three polished guides.
- A compact resource set with checklists, templates, and review gates.
- A publication review note confirming private details have been removed.
- A source-backed research note that separates current product behavior from durable operating principles.

## Non-Goals

- A full course platform.
- A static site stack before the content shape is proven.
- Product-news coverage.
- Claims about unreleased or unverified Codex behavior.
